Blockers & critical path

  • 1 · Web UI is unblocked and highest valueLogin, state, peers and chat already work through the gateway. Doing the UI first makes the demo presentable even if P2P slips.
  • 2 · Files are the next P2P stepDM sessions exist in app/peer.py. Files need FILE_* dispatch, send_file, inbound stream handling, /api/file and files.js. No tracker change is needed.
  • 3 · Crypto is wired and testedX25519 + HKDF + AES-GCM run on every post-handshake packet. Install cryptography from requirements.txt; the remaining review is the transport owner's sign-off. Level 1 still has no peer authentication.
  • 4 · No tracker change needed for P2Ptracker.handle does not implement CONNECT_REQ, but direct connections use roster addresses. INTRO/RELAY are documented non-goals.
  • 5 · Tests are partialtests/test_crypto.py covers the crypto layer; other areas still only have fixtures. The report still needs the 10–20 client stress run and README.
